# Daily Development — 2026-09-28

## Zusammenfassung

Der Backlog kann jetzt über die HTTP-API des ToDo-Viewers gepflegt werden
statt direkt in den Markdown-Dateien. Das ist der neue Standard
(`todo.backend = "api"`). Der Server prüft Format und Regeln, vergibt IDs
und erkennt konkurrierende Änderungen. Der bisherige Datei-Modus bleibt
wählbar (`backend = "files"`) und ist der Rückfall, wenn der Server nicht
läuft. Dann fragt die AI, wie es weitergeht.

Ein neuer Helfer `backlog_api.py` kapselt die API-Aufrufe, und der
todo-Skill beschreibt beide Modi. `backlog.py` kennt jetzt den Papierkorb
des Viewers (Feld `Deleted`). Release `v0.3.0` (nur lokal).

Außerdem wird das Archiv nicht mehr als ganze Datei gelesen: Erst kommt die
flache Liste (jetzt mit Spalte Area), danach holt `backlog.py --show` gezielt
einzelne Einträge. Releases `v0.4.0` und `v0.5.0` (nur lokal).

## Features

### Neu

| Fähigkeit | Praktische Wirkung | Nachweis |
|---|---|---|
| Einstellung `todo.backend` und `todo.api_url` | Pro Projekt wählbar, ob die AI über die API (Standard) oder direkt auf den Dateien arbeitet; die URL ist konfigurierbar (Standard `http://localhost:5411/api/v2`). Bestehende Configs laufen ohne Migration weiter. | `7cd8829`, STORY-032 |
| Helfer `backlog_api.py` | Befehle für Erreichbarkeit, Index, Item lesen/anlegen/ändern, Notes anhängen, Notes und Specs lesen und ersetzen, Papierkorb und Wiederherstellen. Die Quelle zum Backlog-Ordner wird gefunden oder angelegt. Aus einem Worktree heraus wird die Quelle des Haupt-Checkouts benutzt. Endgültiges Löschen gibt es bewusst nicht. Exit-Code 3 bedeutet „Server nicht erreichbar“. | `2494399`, STORY-033 |
| `backlog.py --show <ID> [<ID> ...]` | Gibt im Datei-Modus nur die genannten Einträge aus `TODO.md` oder `archive.md` aus, unverändert und mit Quelldatei. `archive.md` muss dafür nicht mehr ganz geladen werden. Unbekannte IDs enden mit Exit 1. | `ddadd50`, [TASK-015](../todo/items/TASK-015/) |
| Papierkorb im Backlog-Format | `backlog.py` akzeptiert `Deleted: <Datum>.` für Einträge in `archive.md` mit beliebigem Status, lässt sie bei den Parent-Regeln außen vor und markiert sie im Index. | `fbf76b2`, STORY-031 |

### Geändert

| Fähigkeit | Praktische Wirkung | Nachweis |

Fehlende `TODO.md`, unbekanntes Projekt oder abgeschaltetes Modul enden mit Fehler, ohne eine Quelle anzulegen. Neue Quellen von Teilprojekten tragen deren Namen statt des Repo-Namens. | `db4a3c9`, TASK-016 |

## Entscheidungen und Alternativen

| Entscheidung | Grund und Alternativen | Nachweis |
|---|---|---|
| API als Standard, Dateien als Rückfall | Der Server erzwingt Format und Regeln. Verworfen: den Datei-Modus ganz ersetzen, weil nicht jedes Projekt einen ToDo-Viewer hat. | [EPIC-008](../todo/items/EPIC-008/) |
| `format.md` ist maßgeblich | Die Regeln sind in `backlog.py` und im Viewer doppelt umgesetzt. Änderungen kommen zuerst ins Format, danach werden beide nachgezogen. | [EPIC-008](../todo/items/EPIC-008/) |
| Backlog-Commits im API-Modus im Haupt-Checkout | Die API schreibt immer am Pfad der Quelle. Verworfen: eine eigene Quelle je Worktree. | [EPIC-008](../todo/items/EPIC-008/) |
